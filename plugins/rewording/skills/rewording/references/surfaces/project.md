## 3. Project

Voice of Instructions: a standing second-person brief for every chat in the project. One opening sentence for the role, then tagged sections. Stable facts and process, no one-off details.

Paste targets:
- Name: (Optional, a label for people)
- Description: (Optional, a label for people. Keep rules out of it)
- Instructions: (Required)
- Knowledge files: (Required when the work depends on reference material)
- Memory setting: (Required, choose on purpose) In the project's Memory section, turn off "Use account memory" for client, team or sensitive work, so the project's memory stays separate. For one clean chat, turn off Memory in the "+" menu before the first message (V S47).

Instructions template:

```
You [role in one line] for [REQUIRED: who and what].

<context>
[Stable background that holds for every chat.]
</context>

<knowledge_use>
- [file-name.md]: [what it holds]. Read it when [condition].
</knowledge_use>

<process>
1. [Step]
2. [Step]
</process>

<output>
[Default format, length, language.]
</output>

<boundaries>
[What to ask before doing and what never to do, each with a reason.]
</boundaries>
```

Notes:
- Descriptive file names, current versions only, and refer to files by name in Instructions. One-off material goes in chat, because chats in a project share only the Instructions and the knowledge.
- On paid plans retrieval mode turns on when knowledge nears the context limit. No threshold is published. Keep core rules in Instructions and give files clear headings (V S46).
- A new version of Projects is in beta for select users (V S18). Its fields may differ, so use this spec for standard Projects.
